# Lightweight Feature Selection for IDK Cascade Skip Decisions

A two-feature logistic regression matches a Random Forest skip predictor for
real-time IDK cascades — at a **measured 205× lower per-decision cost** on an
NVIDIA Jetson Orin Nano (median 19 µs vs. 3.80 ms, batch size 1, CPU mode).
The Random Forest's entire cascade-latency advantage (at most 2.6 ms/image,
paired bootstrap 95% CI) is smaller than its own per-decision evaluation cost.

**[Read the paper (PDF)](paper/final_paper.pdf)** — IEEE 2-column,
RTSS Work-in-Progress style, 4 pages.

## What this is

*IDK cascades* (Wang et al., 2017) chain classifiers of increasing accuracy and
cost — here ResNet-18 → ResNet-34 → ResNet-152 — where each stage either
commits to a prediction or says "I don't know" and defers to the next. Two
recent RTSS Work-in-Progress papers speed this up by *skipping* the middle
classifier when it is unlikely to help:

- **Nguyen, Cheng & Carroll (RTSS 2024)** skip when the first stage's
  confidence falls below a static 0.3 threshold.
- **Katikaneni, Cheng & Carroll (RTSS 2025)** replace the threshold with a
  Random Forest on three softmax features (confidence, entropy, margin),
  trained to predict whether the middle classifier will abstain.

This project asks the question Katikaneni et al. left as future work: **does a
much simpler predictor suffice?** In a real-time setting the skip predictor's
own WCET is charged against the schedulability budget, so predictor cost is a
first-class concern, not an implementation detail.

## Headline results

Cross-dataset protocol of Katikaneni et al.: predictors trained on the
first-stage-IDK samples of ImageNet-V2 **Matched-Frequency + TopImages**
(8,304 images), evaluated on the full first-stage-IDK population of
**Threshold-0.7** (4,051 images). Everything measured on a Jetson Orin Nano
in CPU mode; brackets are bootstrap 95% CIs.

| Variant | Latency (ms/img) | Top-1 Acc | Skip-F1 | Per-decision cost (median) |
|---|---|---|---|---|
| Baseline (no skip) | 374.86 | 0.549 | — | — |
| Static τ=0.3 (Nguyen 2024) | 363.65 | 0.552 | — | ~0 |
| Random Forest (Katikaneni 2025, re-impl.) | 363.83 | 0.553 | 0.682 [0.667, 0.697] | 3.80 ms |
| **Logistic, 2 features (this work)** | 365.28 | 0.553 | 0.662 [0.647, 0.678] | **19 µs** |

The trained rule is fully interpretable:

```
logit P(skip) = 1.841 − 5.481·conf + 1.785·margin
```

Three honest findings sharpen the story:

1. **The Random Forest's cascade edge is smaller than its own cost.** Its
   paired per-image latency advantage over the logistic is at most 2.6 ms
   (95% CI), less than its 3.80 ms median evaluation overhead. End-to-end, the
   logistic is the cheaper learned rule — and, unlike a tree ensemble, its
   deployed form (two multiplies, two adds, one sigmoid) is branch-free and
   data-independent, so a WCET bound is immediate.
2. **A well-placed static threshold ties both learned rules on this transfer
   target** — consistent with the desktop-CPU caveat in Katikaneni et al.
   themselves.
3. **Confidence alone suffices.** The nested-feature ablation shows the
   one-feature logistic (F1 0.676) matches the two- and three-feature versions
   within CIs — a learned one-feature logistic is exactly a dataset-calibrated
   confidence threshold, connecting the two prior papers directly.

A skip rule breaks even at precision p\* = 1 − t_B/t_C (≈ 0.71 on this board);
both learned predictors operate barely above it (~0.77), which is why
aggressive skipping yields only ~3% latency gains here. The stage-cost ratio,
not the predictor family, is the operative variable.

## Repository layout

```
paper/     LaTeX source + compiled PDF (IEEEtran vendored; tables are
           auto-generated by the code — never hand-edited)
code/      analysis pipeline (see code/README.md)
data/      cached softmax outputs, per-image Jetson Orin Nano timings, labels
           (~345 MB across the three ImageNet-V2 variants, committed so the
           analysis reproduces in seconds without a board or the
           hours-long model-inference step)
figures/   generated plots
Makefile   entry point for everything
```

## Reproduce

```bash
make            # threshold sweep + skip-rule analysis + paper PDF
make sweep      # Nguyen 2024 threshold-sweep table/figure only (seconds)
make rules      # cross-dataset skip-rule training/eval only (seconds)
```

The committed `data/` was produced on a Jetson Orin Nano by
`code/arm_bootstrap.sh` (venv/pip bootstrap + caching + analysis, ~14 h on the
board). `make cache` regenerates it on the current host from the canonical
per-variant ImageNet-V2 release files — only needed if you want fresh timings
for a different platform; predictor-overhead numbers should be measured on the
deployment target (`python3 code/skip_rule.py` profiles the host it runs on;
`--skip-overhead` preserves the committed board numbers).

## Limitations

Work-in-progress scale, honestly labeled: one cascade family (ResNets), one
embedded platform, and a scikit-learn Random Forest as the cost baseline (a
compiled ensemble would narrow — not close — the 205× gap; the paper reports
p99 and max costs as well). The cross-dataset protocol follows Katikaneni et
al. (train Matched-Frequency + TopImages, test Threshold-0.7); other
train/test rotations are future work.
